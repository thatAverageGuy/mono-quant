# ADR-002: Build-Phase Only — No Runtime Quantization

**Date:** 2026-02-03
**Status:** Accepted
**Decider:** thatAverageGuy

## Context

Quantization tools can target two use cases:
1. Build-phase: quantize during CI/CD, ship lightweight artifacts
2. Runtime: quantize on-the-fly at serving time (e.g., bitsandbytes load_in_8bit)

## Decision

mono-quant is build-phase only. Users quantize during development/CI,
save the result, and deploy the quantized artifact. mono-quant is NOT
installed in the deployment environment.

## Rationale

- Clear separation of concerns: build tools ≠ serving tools
- Deployment artifacts have no mono-quant dependency
- Build-phase tools have simpler constraints (no memory pressure, no latency)
- Enables PyTorch-native deployment (quantized → FP32 state_dict for zero-dep load)

## Consequences

- mono-quant is a development/CI dependency, not a production dependency
- No activation quantization at serving time (weights-only quantization)
- Quantized model artifacts are standalone — load with pure PyTorch
- No runtime memory savings from activation quantization
