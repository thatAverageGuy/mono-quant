# ADR-005: QDQ Format for ONNX Export (Not Direct PyTorch Quantized Module Export)

**Date:** 2026-02-04
**Status:** Accepted
**Decider:** thatAverageGuy

## Context

ONNX export of quantized PyTorch models is non-trivial. Options:
1. Export `QuantizedLinear` modules directly via `torch.onnx.export()`
2. Export using QDQ (QuantizeLinear/DequantizeLinear) ONNX nodes
3. Dequantize to FP32, export as standard float model

## Decision

Use QDQ format: revert quantized modules to standard `nn.*` (FP32 weights),
then explicitly insert `DequantizeLinear` nodes into the ONNX graph before export.

## Rationale

PyTorch's `quantized::` operators have NO ONNX opset equivalents. Direct export
of `QuantizedLinear` always fails with:
```
UnsupportedOperatorError: Exporting operator 'quantized::linear' to ONNX opset 17
is not supported.
```

QDQ format:
- Supported by ONNX Runtime, TensorRT, and other runtimes
- Preserves quantization parameters (scale, zero_point) in graph
- Opset 13+ standard for QDQ support
- `revert_to_standard_modules()` (added in v1.1) is the bridge

FP32 export was rejected: loses all quantization information.

## Consequences

- ONNX export always dequantizes weights first (no space saving in ONNX graph)
- ONNX Runtime applies quantization at inference time using embedded QDQ nodes
- INT4 fallback to INT8 for opset < 21 (INT4 tensor type requires opset 21+)
- Validation against ONNX Runtime is required to confirm QDQ nodes are correct
