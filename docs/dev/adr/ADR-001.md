# ADR-001: Model-Agnostic Design — No HuggingFace Dependency

**Date:** 2026-02-03
**Status:** Accepted
**Decider:** thatAverageGuy

## Context

The ML ecosystem is dominated by HuggingFace transformers. Most quantization tools
(bitsandbytes, AWQ, GPTQ) assume HuggingFace models. However:
- Enterprise ML engineers use diverse model sources
- HuggingFace is a heavy dependency (~2GB with transformers)
- Framework lock-in limits adoption

## Decision

mono-quant accepts any `nn.Module`, `state_dict`, or file path. It never imports
`transformers`. Users load their own models.

## Rationale

| Option | Pros | Cons |
|--------|------|------|
| HF-integrated | Easier HF model support | 2GB dep, locks out non-HF users |
| **Model-agnostic** | Works with any PyTorch model | User handles loading |
| PyTorch-only | Maximum simplicity | Limited to base PyTorch formats |

Model-agnostic chosen: fills the niche "just quantize the weights, nothing else."

## Consequences

- Users own model loading (good: flexibility)
- No model architecture awareness (limitation: can't do architecture-specific optimizations)
- No tokenizer support (expected: mono-quant is not a serving tool)
- Verified to work with HF-loaded models, local models, custom models
