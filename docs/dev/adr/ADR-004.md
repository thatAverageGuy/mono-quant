# ADR-004: Local Imports to Break Circular Dependency

**Date:** 2026-02-03
**Status:** Accepted
**Decider:** thatAverageGuy

## Context

`core/quantizers.py` needs to import `modules/linear.py` (to replace modules).
`modules/linear.py` needs to import `core/schemes.py` and `core/mappers.py` (for quantization math).
This creates a circular import that crashes at import time.

## Decision

Move `from mono_quant.modules.linear import QuantizedLinear` imports to local
scope inside functions in `core/quantizers.py` (inside the function body, not at
module level).

## Options Considered

| Option | Pros | Cons |
|--------|------|------|
| Merge into one module | Eliminates circular | Violates single responsibility |
| Dependency injection | Clean architecture | Adds complexity for little gain |
| **Local imports** | Simple, zero boilerplate | Slightly unusual, import not at top |
| Refactor core → types | Clean separation | Significant restructuring |

Local imports chosen: minimal change, proven Python pattern for this exact situation.

## Consequences

- Imports in `core/quantizers.py` are in function scope, not module scope
- Linters may flag this — suppress with `# noqa` or exclude from ruff rules
- Pattern must be documented so contributors don't "fix" it by moving imports to top
- No runtime performance impact (Python caches module imports)
