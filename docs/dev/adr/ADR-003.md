# ADR-003: Dual Interface — CLI + Python API

**Date:** 2026-02-03
**Status:** Accepted
**Decider:** thatAverageGuy

## Context

How should users interact with mono-quant? Options:
1. Python API only (programmatic use)
2. CLI only (CI/CD scripts)
3. Both CLI + Python API

## Decision

Both interfaces. CLI is a thin wrapper over Python API — no quantization logic
exists in CLI code. CLI imports Python API functions and delegates entirely.

## Rationale

- CI/CD pipelines need CLI: `monoquant quantize --model model.pt --bits 8`
- Jupyter notebooks need Python API: `result = quantize(model, bits=8)`
- Having both with shared underlying logic means zero duplication
- CLI = thin wrapper ensures both interfaces stay in sync

## Consequences

- Two entry points registered in pyproject.toml: `monoquant` and `mq` (alias)
- CLI tests require testing through the CLI invocation, not the Python functions
- All new features must be exposed in both interfaces
