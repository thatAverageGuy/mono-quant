# ADR-007: INT4 Fallback to INT8 for ONNX Opset < 21

**Date:** 2026-02-04
**Status:** Accepted
**Decider:** thatAverageGuy

## Context

ONNX's INT4 tensor type (`TensorProto.INT4`) was only introduced in opset 21.
For opset < 21, INT4 quantized models cannot be represented natively in ONNX.
Alternatives:
1. Fail with error
2. Fall back to INT8 with warning
3. Require opset >= 21

## Decision

Fall back to INT8 for opset < 21, with a clear warning message:

```
WARNING: INT4 quantization detected but opset < 21.
Converting to INT8 for ONNX export. Use --opset 21+ for native INT4.
```

## Rationale

- Failing is unhelpful — users who don't care about opset version get a cryptic error
- INT8 fallback produces a valid, loadable ONNX file
- Warning is clear about what happened
- Most ONNX Runtime deployments use opset 13-17, not 21

Opset 21 requirement was rejected: opset 21 support in ONNX Runtime is still maturing
and many deployment targets don't support it yet.

## Consequences

- INT4 models exported with opset < 21 lose precision (INT4 → INT8)
- Users are explicitly warned
- Users who need true INT4 must use `--opset 21` and an ONNX Runtime version
  that supports opset 21 + INT4 tensors
- Detection via `_detect_int4_quantization()` checking for `QuantizedLinearInt4`
